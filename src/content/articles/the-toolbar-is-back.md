For a while, every tool tried to hide its buttons. Commands moved into menus, menus moved into palettes, and the canvas got all the space. It looked calm. It also made people hunt for things they used every minute.

## A smaller, smarter bar

The toolbar is coming back, but it is not the grey strip of icons we remember. The new version floats near the work, holds five or six tools at most, and changes with the selection. Pick a shape and you get shape tools. Pick text and you get type controls.

This is not a new idea. What is new is that teams are finally measuring which tools people reach for, and trimming everything else.

## Why it works

A floating bar keeps the most common actions one click away without covering the canvas. Because it changes with context, it can stay short. Because it stays short, people learn it quickly.

## Where it goes wrong

Context-aware toolbars can move too much. If a button jumps every time the selection changes, people lose their place. The best ones keep a few tools fixed in the same spot and only swap the rest.

## If you are designing one

- Start with usage data, not with a list of features.
- Keep the first three tools in the same place, always.
- Give every icon a label on hover, and a keyboard shortcut people can learn.

The toolbar never really left. It just needed to lose some weight.
